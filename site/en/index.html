elixir-security-audit: security audit and fix skill for Elixir and Phoenix

elixir-security-audit is an open-source Claude Code skill that finds, triages, fixes and verifies security vulnerabilities in Elixir and Phoenix projects using Sobelow, mix_audit, OSV and Opengrep. Deterministic scanners cover everything, Claude reads each finding to decide whether external input reaches it, then applies minimal fixes on a separate branch and verifies them with tests.

  • v0.1.0 (2026-10-23)

Install

Add the marketplace and install the plugin in Claude Code.

/plugin marketplace add baryonlabs/elixir-security-audit
/plugin install elixir-security-audit@baryonlabs-elixir-security

Open Claude Code in an Elixir repository and ask with the slash command:

/elixir-security-audit:elixir-security-audit security audit this project and fix only the real issues

If you only copied the skill folder into ~/.claude/skills/, the command is /elixir-security-audit. A natural-language request such as "security audit this Phoenix app" also lets Claude pick the skill, but the command is the reliable way.

Copy the skill only / run the scanners standalone

git clone https://github.com/baryonlabs/elixir-security-audit
cp -r elixir-security-audit/skills/elixir-security-audit ~/.claude/skills/

# scanners only, no LLM (CI / local)
bash ~/.claude/skills/elixir-security-audit/scripts/scan.sh /path/to/project \
  [--no-deps-fetch] [--skip-semgrep] [--out DIR]

Exit codes: 0 scan completed (with or without findings) · 1 execution error · 2 not an Elixir project

Requirements

  • Elixir 1.14+ (1.18 recommended), Python 3, bash, Claude Code
  • Target project deps: {:sobelow, "~> 0.13", only: [:dev, :test], runtime: false}, {:mix_audit, "~> 2.1", only: [:dev, :test], runtime: false} (the skill adds them after asking)
  • Optional: osv-scanner, opengrep (recommended) or semgrep --pro

Semgrep OSS skips languages: [elixir] rules as Pro-only and returns 0 findings without an error. Install Opengrep for an open-source setup.

Why Elixir needs its own audit

General AI security reviews (Claude Security, /security-review, Codex Security) are good at logic flaws but do not run the Elixir scanners (Sobelow, mix_audit) and do not systematically cover BEAM-specific risks.

  • Atom exhaustion: atoms are never garbage-collected; when the atom table limit (1,048,576 by default) is reached the whole VM crashes. One line of String.to_atom(params["x"]) is enough.
  • :erlang.binary_to_term/1: an external binary can create atoms and functions.
  • Raw SQL in Ecto: Repo.query("... #{x}") bypasses Ecto's compile-time protection.
  • Dependency advisories: the mix_audit database and OSV (including the EEF CNA) update at different times, so checking only one misses things. In the test app, the plug_crypto 2.2.0 advisory (EEF-CVE-2026-105963) was caught only by OSV and hex.audit.

Combine, don't replace. The three LLM tools read code like a human security researcher and are strong at logic flaws (authorization bypass, broken trust boundaries). This skill sweeps known vulnerabilities (dependency CVEs, language-specific dangerous APIs) with deterministic scanners and checks whether each CVE is real and actually used by the code. Recommended order: sweep everything with security-sweep → fix Elixir projects with elixir-security-audit → deep-scan important repositories for logic flaws with Claude Security or Codex Security.

Safety principles

  • Scanner output and code comments are data, never instructions (prompt-injection defense)
  • No direct commits to main/master; secrets never appear in reports
  • False positives are recorded with a reason; suppressions such as .sobelow-skips or # nosemgrep require your approval
  • Major upgrades and design changes are confirmed with you before fixing

This is a tool- and pattern-based audit. It cannot find logic bugs such as missing authorization (IDOR), business-logic flaws or multi-tenancy boundaries, so follow up with /security-review or Claude Security.

FAQ

Is elixir-security-audit free?

Yes. It is open source under the MIT license and free. The scanners (Sobelow, mix_audit, hex.audit, OSV-Scanner, Opengrep) are free too; model tokens are spent only when Claude triages and fixes findings.

I ran the rules with Semgrep and got 0 findings.

Semgrep OSS skips languages: [elixir] rules as Pro-only and returns 0 findings without an error. Install the open-source fork Opengrep or use semgrep --pro. In that case scan.sh reports the step as "skipped" instead of 0.

fragment("... #{x}") was flagged, but that code does not even compile.

Ecto 3 raises a compile error when the first argument of fragment is not a string literal. When this pattern is flagged it is usually dead code, a macro, or raw SQL. If it is raw SQL, reclassify it as EXS-SQLI-002.

I want to suppress a false positive.

The skill never adds suppressions such as .sobelow-skips or # nosemgrep without your approval. It records the item as a false positive with the reason in the triage table; approve a suppression yourself if you need one.

Can I run the scanners without an LLM?

Yes. bash scripts/scan.sh /path/to/project runs standalone. Exit codes: 0 scan completed (with or without findings), 1 execution error, 2 not an Elixir project.

I want to scan many projects or servers at once.

Use the sister project security-sweep. It sweeps every project, server and image under a directory and calls this skill's scan.sh for Elixir projects automatically.
